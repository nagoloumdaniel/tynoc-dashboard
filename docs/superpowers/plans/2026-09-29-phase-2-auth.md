# Phase 2 — Authentification et rôles : plan d'implémentation

> **Pour les agents :** exécuter tâche par tâche (superpowers:executing-plans). Étapes en cases à cocher.

**Objectif :** réserver `/admin` aux administrateurs authentifiés (sessions DynamoDB révocables, RBAC à 3 rôles, anti force brute), en local et en production AWS.

**Architecture :** auth maison suivant le guide Next.js 16. Hash scrypt natif, token opaque en cookie, session en table `Sessions` (TTL), contrôle unique `requireAdmin()` dans une DAL. `proxy.ts` ne fait qu'une redirection UX.

**Stack :** Next.js 16.3, React 19.2, Zod 4, AWS SDK v3 (lib-dynamodb), `@vercel/functions/oidc`, Radix, Vitest 5 (projets unit + integration), Playwright 1.63.

**Spec :** [docs/superpowers/specs/2026-09-29-phase-2-auth-design.md](../specs/2026-09-29-phase-2-auth-design.md)

## Contraintes globales

- Aucune dépendance native : hash via `node:crypto` uniquement.
- Ajout de dépendances : `pnpm add --lockfile-only <pkg>` puis suppression de `node_modules` (`cmd //c "rd /s /q node_modules"`) et `pnpm install` (EPERM sinon sous Windows).
- Scripts Node qui importent `src/` : `tsx --conditions=react-server --env-file-if-exists=.env.local`.
- Toute page ou action admin appelle `requireAdmin()`.
- Textes d'interface en français ; code et identifiants en anglais.
- Tables de test : préfixe `tynoc-test-` sur DynamoDB Local `http://localhost:8000`.
- Chaque tâche : tests verts, `pnpm ci:local`, commit Conventional Commits, push (le hook pre-push relance la CI locale).

### Tâche 2 : Hash des mots de passe

**Fichiers :** créer `src/lib/auth/password.ts`, `src/lib/auth/password.test.ts`

**Interfaces :** `hashPassword(plain: string): Promise<string>`, `verifyPassword(plain: string, stored: string): Promise<boolean>`, `dummyHash(): Promise<string>`

- [ ] **2.1** Tests :

```ts
it("verifies the password it hashed", async () => {
  const hash = await hashPassword("correct horse battery");
  expect(hash).toMatch(/^scrypt\$32768\$8\$1\$/);
  expect(await verifyPassword("correct horse battery", hash)).toBe(true);
});
it("rejects a wrong password", async () => {
  expect(await verifyPassword("wrong", await hashPassword("right"))).toBe(
    false,
  );
});
it("salts every hash", async () => {
  expect(await hashPassword("same")).not.toBe(await hashPassword("same"));
});
it.each(["", "bcrypt$x", "scrypt$abc$8$1$AA$AA", "scrypt$32768$8$1$$"])(
  "returns false for malformed hash %s",
  async (stored) => {
    expect(await verifyPassword("x", stored)).toBe(false);
  },
);
```

- [ ] **2.2** Échec attendu, puis implémentation : `randomBytes(16)`, `scrypt(plain.normalize("NFKC"), salt, 64, { N: 32768, r: 8, p: 1, maxmem: 64 * 1024 * 1024 })` enveloppé dans une `Promise`, format `scrypt$N$r$p$sel$hash` en base64, `timingSafeEqual`, bornes `N` puissance de 2 ≤ 2^20, `r` ≤ 16, `p` ≤ 4, clé 64 octets. `dummyHash()` mémorise le hash d'un mot de passe fixe.
- [ ] **2.3** Tests verts → commit `feat(auth): add scrypt password hashing` → push.

  ["SUPER_ADMIN", "admins:manage", true],
  ["ADMIN", "products:write", true],
